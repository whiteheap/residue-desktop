# Agent guide: the Mac app

The residue Mac app is a Tauri 2 app over the residue CLI in this repository: Rust in `src-tauri/`, React and TypeScript in `src/` (Kumo components, Phosphor icons, Tailwind 4). The root [README](../README.md#mac-app) is the user contract; [app/README.md](README.md) has the build. The root [AGENTS.md](../AGENTS.md) holds for everything here, and these rules add to it.

## Invariants

These are why the app can be trusted with someone's worktrees. Do not weaken them without a decision recorded in the CHANGELOG.

- The app never reimplements a check, a verdict, a size or a deletion. Every action runs the residue binary bundled as the sidecar (`src-tauri/src/cli.rs`) with explicit arguments, stdin from `/dev/null` and a deadline, and reads its `--json` document. When residue gives no value, show residue's own words or an unavailable state, never a guess.
- Every child the app starts, residue or not, starts through `cli::spawn` (`cli::Run` calls it), one start at a time, so on macOS no child inherits another's pipes (#116). `src-tauri/clippy.toml` refuses `Command::spawn`, `output` and `status` anywhere else.
- Removal is `residue remove --trash --json PATH...` (`src-tauri/src/lib.rs`, `remove`). The confirmation first shows residue's plan: the same command without `--yes`, which removes and purges nothing because stdin is not a terminal (exit status 3, each ready worktree skipped with verdict `candidate`). Nothing is removed without a click on the confirm: only that click runs it again with `--yes` and exactly the planned paths. Never `--no-trash`, never `--all`, never a scan root as a path.
- A failure to draw stays in the part that failed: each screen and each dialog has its own `ErrorBoundary`. A dialog's draws its panel in a dialog whose one way out is Close, which returns to the screen's fresh read: drawing the dialog again would start its flow again after its action may have run. The panel never says that nothing changed, since the result of a confirmed action may be what failed to draw.
- Restore runs only `residue restore --json ENTRY`, with a trash entry's or a removal record's `entry_path`. Listing runs `residue restore --json` in each folder and shows both `trash` and `removed`. A record's row says before the click what restore does not bring back (its `not_kept` ignored entries) and offers Restore only for a state it knows restore takes: `removed`, `interrupted` and `back` (Git lists the worktree at its path again; restore gives it what it lacks of the record). None for a record residue cannot read (`error`, `incomplete`), one it cannot tell is back (`unknown`, with `back_error`), or a state a newer residue adds.
- Automatic cleanup runs `residue service install`, `uninstall` and `status` (`src-tauri/src/service.rs`). It installs from a residue the user installed that is at least as new as the bundled one, or else from the app's own copy in `~/Library/Application Support/com.whiteheap.residue/bin/`, never from the binary inside the app bundle: the service records the binary's path, and the app can move or be deleted.
- What the window says the service does comes from the service's arguments and the version of the binary it runs (`service.rs`, `watch_settings`), never from the bundled residue: `brew upgrade` changes the service's binary without the app. residue's defaults for options a service does not set are the `DEFAULT_*` constants in `service.rs` (`DEFAULT_KEEP_REMOVED` is `cli::DEFAULT_KEEP_REMOVED`), and `FETCH_SINCE` is the first release that fetches. Copy that says how long removal records last names the service's `--keep-removed` when it sets one, else that default, and says which. Saving folders passes every one of the service's options on as written, including an option the app does not know, such as one a newer residue adds (`parse_watch`: it takes the next argument as its value unless that is an option or an absolute path). Never drop an option on a save. An argument that is neither an option nor a folder blocks the save (`Plan.blocked`), never a fall back to defaults. The preview is the saved service's pass: `watch --once --dry-run` with every option a save keeps, by the binary a save installs with, so it fetches when the service would. A save installs what its dialog showed or nothing: the dialog plans from its own read, made when it opens, and sends that read's `Basis` back (the binary a save installs with and its version, the options it keeps, and the running service's binary, version, folders and `--dry-run`); `install` reads again and, when any of it differs, installs nothing and returns what changed (`Save::Changed`). Never plan a save from the screen's read, and never drop a field from the basis. Other text about residue's behavior states what the CLI in this repository does: a change to a `watch` option, a default or a JSON document in `src/` updates the constants, `src/lib/types.ts` and that text in the same pull request.
- The bundled residue is the CLI from the same commit, with the same version, never a download or a committed binary. It is `Contents/MacOS/residue-cli`: the app's own executable is `residue` (the Cargo `[[bin]]`), the name macOS shows, so a lookup of the CLI never takes `residue` beside the app, and a PATH search skips the app's own executable (`find_installer`). `scripts/sidecar.sh` builds it from the root, or, in the release, joins the binaries of the release's own macOS archives; `release.yml` checks each architecture's UUID against those archives.
- One version: the root `Cargo.toml`. `tauri.conf.json`, `package.json` and `src-tauri/Cargo.toml` hold none; `scripts/tauri.sh` passes it to Tauri. Never add a second copy.
- The app's crate stays out of the CLI: the root `Cargo.toml` excludes `app/`, and `src-tauri/Cargo.toml` keeps its own `[workspace]` table. Never make the root a workspace with the app in it.
- Charts draw residue's numbers and shares of them, nothing else: `src/lib/viz.ts` turns residue's documents into shapes and `src/components/viz/` draws them. Emphasis is their one visual variable (`Tone`: bright, gray, hatched, rest), never a hue, and in forced colors each tone keeps a fill, an outline or the hatch. Every chart has a text equivalent on its screen (its caption, its legend's values, the list or the table), and nothing is reachable only through a chart. Never draw a count-down such as "days left": residue deletes a trash entry at the first removal or automatic cleanup in its repository after `--keep-trash`, not on a date.
- Development aids stay out of release builds: `devshot.rs` compiles only for macOS debug builds, and the service preview (`DevPreview`) checks `cfg!(debug_assertions)`.

## Text

The root [AGENTS.md](../AGENTS.md#text-and-cost) rule holds on every screen and dialog. A button names its action and its object ("Move 3 to the trash", "Turn off automatic cleanup"), never "OK". A rule few readers need before they act, such as when a removal record is forgotten, goes in a disclosure.

## Cost

The root [AGENTS.md](../AGENTS.md#text-and-cost) rule holds. Measure memory as `footprint -p PID` of the app, its WebContent and its GPU process, and CPU as `ps -o time= -p PID` before and after a fixed task (#90).

- Tailwind scans only `src/` and the chunks of the Kumo components the app draws, listed in `src/styles.css`. Importing another Kumo component adds its chunk there, or it renders unstyled.
- What follows the pointer is written to its element, not to state: a render of the Worktrees map draws every tile.
- residue's JSON reaches the window as the text residue printed (`cli::Document`). The app reads only its `schema`.

## Verify a change

On a machine that runs residue's service, its user's data and service are not test fixtures:

- Never run `residue service install` or `uninstall`, `--dry-run` and a scratch `HOME` included. launchd acts on the real login session (`gui/UID`) and the label `com.whiteheap.residue.watch` is shared, so either one replaces or removes that user's service. Run the app with `RESIDUE_APP_DEV_SERVICE=preview` to exercise the switch: it runs only `residue watch --once --dry-run`, which removes nothing. `residue service status` only reads.
- Remove and restore only in scratch repositories you create in a temporary folder. A scan of real folders only reads, and is fine for a realistic overview.
- To see the UI from a terminal that cannot record the screen, run `pnpm tauri dev` with `RESIDUE_APP_DEV_SNAPSHOT_DIR=DIR` and write a name into `DIR/request` (app/README.md, "Development builds").

Then run what CI runs (app/README.md, "Checks"). A change to the release workflow is proved by the dry run its pull request starts, which attests and publishes nothing.
